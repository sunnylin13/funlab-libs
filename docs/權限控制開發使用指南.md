# 權限控制開發使用指南

本指南只講「怎麼用＋必須遵守的規則」。實作機制以程式碼說明為準
（`funlab/core/auth.py`、`policy.py`、`plugin.py`）。

## 一、三層守門，按範圍選用最外層可行的

| 範圍 | 用具 | 例 |
|---|---|---|
| 整個 Blueprint 同一政策 | `default_route_policy`（構造級守門，**首選**） | fundmgr／sse／option＝登入者；quotesvcs＝管理員 |
| Blueprint 內個別路由加严 | `@policy_required(policy)` | 登入者頁面中的 admin-only API |
| 單一路由豁免 default policy | `@Plugin.skip_default_policy` 或 `default_route_exempt_endpoints` | 健康檢查端點 |

選擇準則：**整套同政策一律用 `default_route_policy`**，逐路由裝飾器只用於混合權限面。
逐路由標記會漏掛；構造級守門不會。

## 二、標準寫法

### Blueprint 層級（首選）

```python
from funlab.core.plugin import Plugin
from funlab.core.policy import is_authenticated_user

class MyView(Plugin):
    # 必須用 staticmethod 包住（慣例；直接掛函數靠框架救援才正確，勿依賴）
    default_route_policy = staticmethod(is_authenticated_user)
    default_route_exempt_endpoints = {'health'}   # 依 endpoint 名豁免

    def _on_init(self):
        self._register_routes()

    def _register_routes(self):
        @self.blueprint.route('/ping')
        @Plugin.skip_default_policy               # 單一路由豁免
        def ping():
            return 'pong'
```

### 路由層級

```python
from funlab.core.auth import policy_required
from funlab.core.policy import is_admin, is_supervisor, is_authenticated_user

@self.blueprint.route('/api/reload', methods=['POST'])
@policy_required(is_admin)
def reload_config(): ...
```

### 共用 policy（`funlab.core.policy`）

只用這四個原語，複合條件在 view 內以 if＋`abort(403)` 處理：

- `is_admin(user)`
- `has_role(user, *roles)` — 大小寫不拘
- `is_supervisor(user)`
- `is_authenticated_user(user)`

`admin_required`／`role_required` 為遺留 API（業務碼已零使用），僅供相容維護，
新代码一律 `policy_required` ＋ policy 原語。

## 三、必須遵守的規則

1. **default_route_policy 一律 `staticmethod(...)` 包住**。直接掛一般函數目前也能跑
   （框架有 descriptor 救援），但語意隱晦，禁止新代码使用。
2. **選單隱藏 ≠ 路由防護**。`MenuItem(required_policy=...)` 只在選單建構期決定可見性，
   不保護任何路由；每個路由仍須由上表三層之一保護。兩者是平行機制，admin 面通常兩邊都掛。
3. **資源級權限在 view 內做**，decorator 管不到「这笔資料是不是你的」。範本
   （fundmgr）：先取資源、比對擁有者、非擁有者且非 supervisor 即 `abort(403)`，
   收斂成 helper 函數，勿在各 view 內散寫比較式。
4. **未登入的表現由框架決定**：authorization 開啟→導向登入頁；PUBLIC 模式→403
   （fail-closed）。不要自己寫導向。
5. **啟動 fail-closed**：安全元件（`provides_security=True`）啟動期載入失敗會直接拒絕
   啟動 app（AUTH-03），不會降回 PUBLIC 續跑；`security_mode='required'` 的 plugin
   在無 auth provider 時不啟用。開發時勿試圖繞過這兩個守門。
